# 문서 작성 및 배포 가이드 (비개발자용)

이 문서는 개발 도구나 터미널에 익숙하지 않은 담당자가 **Obsidian**을 이용해 도뉴 사용 가이드를 작성·수정하고, GitHub에 푸시(반영)하는 방법을 안내합니다.

> [!info]
> 이 문서는 상단에 `publish: false`가 설정되어 있어 **내부 작업자용으로만 사용되며, 실제 웹 가이드 사이트에는 노출되지 않습니다.**

---

## 1. 작업 시작 전 준비

1. **Obsidian 실행 후 `vault` 폴더 열기**
   * 로컬 프로젝트 폴더 안의 `vault` 폴더를 Obsidian 보관함(Vault)으로 엽니다.
2. **최신 문서 불러오기 (Pull)**
   * 다른 작업자가 먼저 수정한 내용과 겹치지 않도록 작업을 시작하기 전에 최신 내용을 받아옵니다.
   * Obsidian을 실행하면 자동으로 최신 내용을 받아오도록 설정되어 있지만, 작업 직전에 한 번 더 확인하는 것이 안전합니다.
   * 단축키 **`Cmd + P`** (Windows는 `Ctrl + P`)를 누르고 **`Git: Pull`** 을 입력해 실행합니다.

---

## 2. 새 문서 작성 방법

### ① 파일 만들기
1. 왼쪽 파일 탐색기에서 문서를 추가할 **카테고리 폴더**를 우클릭한 뒤 **[New note]** 를 클릭합니다.
2. 문서 제목이 곧 웹 페이지 주소와 메뉴 이름이 되므로, 내용을 잘 나타내는 한글 제목으로 이름을 정합니다. (예: `계약서 서명 방법`)

### ② 문서 상단 속성(Frontmatter) 작성하기
문서 맨 첫 줄에 `---`로 감싼 속성 영역을 넣습니다.

```markdown
---
title: "문서 제목"
---
```

* 아직 공개할 준비가 되지 않은 문서는 아래처럼 `publish: false`를 추가하면 웹 사이트에 노출되지 않습니다.

```markdown
---
title: "작성 중인 문서"
publish: false
---
```

### ③ 본문 작성 규칙
* **소제목 구분:** `## 큰 제목`, `### 작은 제목` 형태로 단계를 나눕니다.
* **버튼·메뉴 강조:** 화면의 버튼이나 메뉴 이름은 `**[버튼명]**`처럼 굵게 표시합니다.
* **이미지 추가:**
  * 스크린샷을 복사해 본문에 바로 붙여넣거나, `vault/assets` 폴더에 이미지를 넣고 `![[이미지파일명.png]]` 형태로 작성합니다.
  * 이미지 두 개를 가로로 나란히 배치하려면 줄바꿈 없이 `![[이미지1.png]]![[이미지2.png]]`처럼 이어서 작성합니다.
* **다른 가이드 문서 링크:** `[[폴더명/문서명|화면에 표시할 글자]]` 형태로 연결합니다.
  * 예: `[[계약 생성/계약 생성|계약 생성 방법]]`
* **안내 박스(Callout) 사용:** 주의사항이나 팁은 아래 형식으로 강조할 수 있습니다.

```markdown
> [!note] 참고
> 일반 안내 내용을 적습니다.

> [!tip] 팁
> 도움이 되는 추가 정보를 적습니다.

> [!warning] 주의
> 작업 시 주의해야 할 내용을 적습니다.

> [!danger] 경고
> 복구가 불가능하거나 매우 중요한 경고를 적습니다.
```

### ④ 사이드바 메뉴 순서 등록 (`sortspec.md`)
새 문서를 만들었다면 **반드시 `vault/sortspec.md` 파일에도 문서 이름을 추가**해야 웹 가이드 왼쪽 메뉴(사이드바)에 원하는 순서대로 표시됩니다.

1. 왼쪽 탐색기에서 `sortspec` 문서를 엽니다.
2. 위쪽 `sorting-spec:` 영역에서 해당 폴더 이름(`target-folder: 폴더명`) 아래에 새 문서 이름을 한 줄 추가합니다. (확장자 `.md`는 쓰지 않습니다.)
3. 저장하면 Obsidian 탐색기와 웹 가이드 메뉴 순서가 함께 반영됩니다.

---

## 3. 기존 문서 수정 방법

1. 왼쪽 탐색기에서 수정할 문서를 클릭해 내용을 바로 고칩니다. (Obsidian은 수정 내용을 자동 저장합니다.)
2. **파일 이름이나 폴더를 바꾼 경우** 아래 두 가지를 함께 확인해 주세요.
   * `vault/sortspec.md`에 적힌 문서 이름도 바뀐 이름에 맞게 수정하기
   * 다른 문서에서 해당 문서를 `[[...]]`로 링크하고 있다면 링크 경로도 함께 수정하기
3. 기존 문서를 웹에서 잠시 내리고 싶다면 문서 맨 위 속성(`---` 안쪽)에 `publish: false`를 추가합니다.

---

## 4. 변경 사항 푸시(반영) 방법

문서 작성이나 수정이 끝나면 내 컴퓨터에만 저장된 내용을 원격 저장소(GitHub)로 올려야 웹 가이드에 반영됩니다.

### 방법 A: Obsidian 안에서 바로 푸시하기 (권장)

이 보관함에는 **Obsidian Git** 플러그인이 이미 설정되어 있어, 별도 프로그램 없이 Obsidian 안에서 바로 푸시할 수 있습니다.

1. **`Cmd + P`** (Windows는 `Ctrl + P`)를 눌러 명령 팔레트를 엽니다.
2. **`Git: Commit-and-sync`** 를 검색해 선택합니다.
   * 이 명령은 **변경 사항 저장(Commit) → 최신 내용 받기(Pull) → 올리기(Push)** 를 한 번에 처리합니다.
3. 커밋 메시지 입력 창이 뜨면 수정한 내용을 간단히 적고 Enter를 누릅니다.
   * 예: `계약 생성 가이드 이미지 교체` 또는 `요금제 해지 안내 문구 수정`
   * 따로 적지 않고 기본 메시지를 그대로 사용해도 됩니다.
4. 오른쪽 아래 상태 표시줄이나 알림창에 푸시 완료 메시지가 뜨면 끝납니다.

> [!tip] 변경된 파일 목록을 눈으로 확인하고 싶다면
> Obsidian 오른쪽 사이드바의 **Git(소스 컨트롤)** 아이콘을 열면, 어떤 파일이 수정·추가되었는지 확인하고 커밋/푸시 버튼을 눌러 진행할 수도 있습니다.

### 방법 B: GitHub Desktop 앱 사용하기

Obsidian Git 실행 중 오류가 나거나 GUI 화면으로 확인하고 싶을 때는 GitHub Desktop을 사용할 수 있습니다.

1. **GitHub Desktop**을 열고 현재 프로젝트(`donue-guide`)가 선택되어 있는지 확인합니다.
2. 왼쪽 **Changes** 목록에서 내가 수정한 파일들이 체크되어 있는지 확인합니다.
3. 왼쪽 아래 **Summary** 칸에 수정 내용을 간단히 입력한 뒤 **[Commit to main]** 버튼을 클릭합니다.
4. 상단 **[Fetch origin]** 또는 **[Pull origin]** 이 보이면 먼저 눌러 최신 내용을 받고, **[Push origin]** 버튼을 클릭해 반영합니다.

---

## 5. 자주 묻는 질문 및 주의사항

* **푸시했는데 웹 사이트에 바로 안 보여요.**
  * 푸시 후 빌드 및 배포 과정이 진행되므로, 실제 웹 사이트에 반영되기까지 몇 분 정도 걸릴 수 있습니다.
* **충돌(Conflict) 오류가 났어요.**
  * 같은 문서의 같은 줄을 다른 사람과 동시에 수정했을 때 발생합니다. 임의로 파일을 지우거나 덮어쓰지 말고, 오류 화면을 캡처해 담당 개발자에게 전달해 주세요.
* **이미지가 깨져 보여요.**
  * 이미지 파일이 `vault/assets` 폴더 안에 정상적으로 저장되어 있는지, 파일 이름의 띄어쓰기나 확장자(`.png`, `.jpg`)가 본문 링크(`![[...]]`)와 정확히 일치하는지 확인해 주세요.
